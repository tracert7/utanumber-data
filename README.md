# 우타넘버 공개 데이터

TJ 신규 일본곡·JPOP TOP100 메타데이터 전용 서비스. TJ미디어 공식 서비스가 아닙니다. 음원·가사·앨범 이미지·이용자 저장 목록·인증정보는 포함하지 않습니다.

갱신 예약은 한국 시간06:17·10:17·14:17·18:17·22:17입니다. GitHub 예약은 지연될 수 있습니다. 각 목록의 확인 시각과 공식 출처는 discovery.json에 기록합니다.

`npm ci && npm run refresh`는 외부 요청 없는 배포파일 회귀검증을 먼저 통과한 후 TJ 공식 공개 메타데이터를 갱신합니다. robots와 요청 간격/횟수 제한, 익명 CSRF 절차를 지키며401/403/429에서는 중단하고 접근 제한 기록을 보존합니다. 실패한 목록은 마지막 검증 목록을 유지하고 오류를 숨기지 않습니다.

## 제목 정책과 재발 방지

검수한 제목/가수/별칭과 공식 번호·곡 버전 식별을 유지합니다. 폐기된 옛 뜻풀이 사전을 신곡에 주입하지 않습니다. 허용되지 않는 데이터 필드에 대한 검증은 유지합니다. `cloud-build.json`은 배포 코드/seed와 원본 입력의 해시를 기록합니다. `node cloud-self-test.mjs`는 실제 배포 실행파일로 옛 source 포함 자료·신곡 목록·실패 보존·차단 보존을 검사하고 TJ에는 연결하지 않습니다.

## 서버 자동 점검

`.github/workflows/health.yml`은 매시간37분과 갱신 workflow 종료 직후 GitHub 서버에서 실행됩니다. `node monitor.mjs`는 공개 JSON의 스키마/TOP100100곡/번호·순위 중복/각 목록12시간 신선도/오류/CORS를 검사합니다. TJ 조회나 배포를 하지 않습니다. 실패 보고서는 Actions artifact에14일 보관됩니다. 기존 실패 알림을 유지하며 PC나 Codex를 켜둘 필요가 없습니다.

## 복구

배포 전 코드/seed/state를 별도로 백업합니다. `state.json.gz`에는 마지막 정상 목록과 접근 제한 기록이 있으므로 오래된 로컬 파일로 덮어쓰거나 지우지 않습니다. 코드 문제는 이전 검증 코드/seed로 되돌릴 수 있고 현재 state는 보존합니다. 실제 성공 여부는 workflow와 공개 JSON을 대조해야 합니다.

## 신곡 한국어 표기 자동 조사

공식 갱신 후 출처 기반 제목 조사가 이어집니다. 짱짱이 블로그 가수별 메타데이터943개 색인과8개 허용 블로그의 공개 검색/RSS를 사용하며 원제·가수·버전이 정확히 맞는 단일 한국어 표기만 자동 반영합니다. 충돌/미확인은 별도 큐에 남겨12시간 뒤 재조사하고, 한 번의 실행은6곡/16요청, 호스트별 하루24요청, 최소1.5초 간격으로 제한합니다. robots/차단/요청 예산을 지키며401/403/429는 이후 실행에도 해당 출처 요청을 중단합니다. 원문 우선 표시는 유지하고 검수된 한국어 별칭을 먼저 전달해 기존 출시 앱에서도 괄호 표기가 가능합니다. 가사·타사 번호·음원·사진은 저장하지 않습니다.

동적 검수표·대기 큐·출처 캐시·요청/차단 기록은 state.json.gz 안의 data/discovery/title-research-state.json으로 계속 보존됩니다. title-research.json은 처리 현황, title-reviews.json은 새로 확인된 표기와 근거를 공개합니다. 기존 discovery.json 스키마와 URL은 유지합니다. 자동 health는 보고서와 실제 목록의 연결·신선도·누락을 비교하고 일본어 제목이24시간 이상 미해결이거나 조사 상태 손상이면 실패합니다. 못 찾은 표기는 번역 완료로 표시하지 않으며 원제를 보존합니다.
